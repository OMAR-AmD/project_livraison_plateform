\section{Pourquoi la s\'ecurit\'e}
SwiftDeliver manipule des adresses clients, des positions GPS en temps r\'eel, des paiements et trois niveaux de privil\`eges, avec un assistant conversationnel outill\'e capable d'annuler une livraison. La fraude logistique moderne (GPS falsifi\'e, fausse livraison, r\'epudiation) est un probl\`eme de donn\'ees comportementales, pas d'attaque r\'eseau classique : c'est ce qui rend l'axe s\'ecurit\'e pertinent pour un profil Data/IA.

Les autres axes ont \'et\'e \'ecart\'es pour des raisons v\'erifiables : le moteur OSRM ($\sim$820 Mo RAM, 1,7 Go de donn\'ees) exclut les offres Cloud gratuites ; il n'existe aucun capteur ni protocole IoT dans le syst\`eme ; le frontend est responsive mais sans PWA ni notifications push. La s\'ecurit\'e est le seul axe avec du code existant et une extension d\'emontrable en local \`a co\^ut z\'ero.

Mod\`ele d'attaquant : le HMAC prot\`ege contre un attaquant avec acc\`es \`a la base \textbf{sans} la cl\'e serveur, pas contre un attaquant poss\'edant les deux. Le GPS reste d\'eclaratif : la d\'emo utilise une simulation assum\'ee.

\section{Ce qui sera livr\'e (p\'erim\`etre ferm\'e)}
\textbf{Sprint~1 -- Preuve de livraison scell\'ee.} \`A chaque passage \`a DELIVERED : position exig\'ee (Redis en priorit\'e, fra\^\i cheur TTL 30~s contr\^ol\'ee, refus si divergence avec la requ\^ete), distance Haversine contre la destination avec refus au-del\`a de 500~m (seuil configurable), sceau \textbf{HMAC-SHA256} \`a cl\'e serveur couvrant (commande, livreur, client, position, horodatage), \textbf{cha\^\i nage par livreur} avec ancrage, \textbf{OTP 4--6 chiffres} g\'en\'er\'e \`a \texttt{IN\_TRANSIT} et saisi par le livreur. Sortie de secours : signalement avec validation admin trac\'ee.

\textbf{Sprint~2 -- Garde-fou de trajectoire livr\'e.} Comparaison de la position courante \`a la polyline OSRM dans le backend Java existant, seuils de d\'eviation et d'arr\^et, alertes.

\textbf{Durcissement.} Audit IDOR des endpoints existants d'abord, rate limiting du login, \texttt{tokenVersion}, jeu de 20--30 attaques chatbot class\'ees OWASP Top~10 for LLM, CI s\'ecurit\'e (Trivy/gitleaks), \'etat de l'art court.

Le RLS PostgreSQL est hors p\'erim\`etre : incompatible avec le pool JPA mono-utilisateur sans refonte.

\section{Protocole de mesure}
Calibration et test s\'epar\'es : les seuils sont r\'egl\'es sur un jeu, \'evalu\'es sur un autre. Mod\`ele de bruit GPS justifi\'e (plus fort en ville), validation possible sur traces r\'eelles publiques (GeoLife). Mesures : taux de faux refus du seuil 500~m ; surco\^ut de latence du scellement ; pr\'ecision/rappel du garde-fou ; attaques chatbot en 20--30 cas pr\'esent\'es comme un petit \'echantillon. Pour le chatbot, deux mesures distinctes : r\'eussite \textbf{au niveau du mod\`ele} (probabiliste, Llama~1B fragile) vs \textbf{action ex\'ecut\'ee} (d\'eterministe, contr\^ol\'ee serveur) -- la seconde doit tomber \`a z\'ero, c'est l'argument central.

\textbf{Volet data (fili\`ere Data/IA).} Le garde-fou \`a r\`egles sert de baseline ; un notebook Python hors ligne en extrait quelques variables (\'ecart \`a la polyline, dur\'ee d'arr\^et, \'ecart de dur\'ee vs OSRM) et compare un mod\`ele simple (Isolation Forest ou r\'egression logistique) \`a la baseline, pr\'ecision/rappel c\^ote \`a c\^ote. Pas de microservice, pas de d\'eploiement ; les heures sont prises sur le poste mesures, que le notebook sert aussi \`a produire.

\section{Planning 100~h (16~h effectu\'ees, 84~h restantes)}
Les 16~h couvrent l'audit existant et le d\'ebut du Sprint~1. Reste : audit IDOR + Sprint~1 blind\'e (22~h, sortie de secours minimale : un endpoint, un statut, une ligne de journal), suite adversariale chatbot (12~h), Sprint~2 + journal cha\^\i n\'e (22~h ; si manque de temps, sacrifier l'ancrage ou le notebook, pas le garde-fou), durcissement auth (8~h), mesures + menaces + \'etat de l'art (10~h), \textbf{rapport et soutenance (10~h)}. Total 100~h, z\'ero d\'epense, z\'ero d\'eploiement. Hypoth\`ese : ces 100~h couvrent tout le projet ; sans marge, toute ligne Pr\'evu non livr\'ee est reclass\'ee en limite avant la soutenance.

\section*{Conclusion}
Menaces identifi\'ees, contr\^oles impl\'ement\'es, efficacit\'e mesur\'ee : c'est ce r\'ecit, pas l'ajout de fonctionnalit\'es, qui fait un travail d'ing\'enieur.
